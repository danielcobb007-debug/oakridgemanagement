# AUDIT CHECKLIST

## Purpose

This checklist standardizes operational audit procedures across the ORM ecosystem.

Its purpose is to identify:

- governance drift
- architectural inconsistency
- deployment mismatch
- namespace violations
- undocumented restructuring
- AI operational drift
- repo integrity issues

This checklist should be used periodically and before major deployments, migrations, restructures, or standards changes.

---

# GOVERNANCE AUDIT

## Authority Verification

- [ ] Verify source-of-truth hierarchy alignment
- [ ] Verify governance documents remain authoritative
- [ ] Verify escalation rules are being followed
- [ ] Verify change-control sequencing is intact
- [ ] Verify no undocumented governance assumptions exist

---

## Documentation Consistency

- [ ] Verify governance docs align with repo structure
- [ ] Verify architecture docs align with implementation
- [ ] Verify standards boundaries remain consistent
- [ ] Verify no conflicting documentation exists

---

# ARCHITECTURE AUDIT

## Namespace Verification

- [ ] Verify file placement consistency
- [ ] Verify namespace ownership clarity
- [ ] Verify platform boundaries remain intact
- [ ] Verify no undocumented structural changes occurred

---

## Implementation Mapping

- [ ] Verify source-file ownership
- [ ] Verify route mapping consistency
- [ ] Verify deployment alignment
- [ ] Verify no orphaned implementation exists

---

# DEPLOYMENT AUDIT

## Repo Integrity

- [ ] Verify clean git state
- [ ] Verify branch synchronization
- [ ] Verify commit traceability
- [ ] Verify rollback clarity
- [ ] Verify no unresolved merge conflicts exist

---

## Production Verification

- [ ] Verify production matches governed intent
- [ ] Verify route behavior consistency
- [ ] Verify deployment verification occurred
- [ ] Verify no undocumented hotfixes exist

---

# AI OPERATIONS AUDIT

## AI Governance Verification

- [ ] Verify AI role boundaries remain intact
- [ ] Verify conversational outputs are not overriding governance
- [ ] Verify markdown truth remains authoritative
- [ ] Verify AI-generated restructuring followed governance review

---

## Operational Consistency

- [ ] Verify no parallel truth systems exist
- [ ] Verify AI orchestration remains aligned
- [ ] Verify implementation suggestions remain architecture-aligned

---

# STANDARDS AUDIT

## Standards Governance

- [ ] Verify standards boundaries remain clear
- [ ] Verify terminology consistency
- [ ] Verify methodology alignment
- [ ] Verify public/private standards separation
- [ ] Verify commercialization boundaries remain governed

---

# DRIFT RESPONSE

## If Drift Is Identified

- [ ] Classify drift severity
- [ ] Stop uncontrolled implementation if necessary
- [ ] Escalate ambiguity if required
- [ ] Reconcile governance documentation
- [ ] Normalize operational state
- [ ] Document resulting decisions

---

# NON-NEGOTIABLE RULE

If operational reality cannot be verified against governed truth, the system is considered out of alignment until reconciled.
