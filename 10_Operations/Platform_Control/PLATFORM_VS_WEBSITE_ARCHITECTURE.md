# PLATFORM VS WEBSITE ARCHITECTURE

## Purpose

This document defines the distinction between the Oak Ridge Management platform layer and its website/public presentation layer.

Its purpose is to prevent:

- website content from becoming unintended governance truth
- SEO or marketing decisions from overriding platform architecture
- public page structure from dictating institutional structure
- implementation shortcuts from becoming permanent operating assumptions
- AI systems from confusing presentation work with platform governance

---

## Core Principle

The website is a rendered surface of the platform.

The platform is not the website.

---

## Platform Layer

The platform layer includes:

- governance
- methodology
- operating logic
- standards architecture
- institutional memory
- workflow design
- AI orchestration rules
- deployment discipline
- source-of-truth documentation
- decision history
- commercial strategy
- intellectual property structure
- capital/infrastructure frameworks

The platform exists even if no public website exists.

The platform is governed through markdown artifacts, repo structure, decision logs, system maps, and implementation rules.

---

## Website Layer

The website layer includes:

- public pages
- SEO surfaces
- marketing language
- navigation
- calls to action
- conversion flows
- visual design
- route structure
- public-facing content
- downloadable assets

The website communicates selected parts of the platform.

It does not define the platform.

---

## Relationship Between Platform and Website

The website should be downstream from the platform.

Platform governance determines:

- what is true
- what is approved
- what is canonical
- what is sensitive
- what may be public
- what requires caution
- what should remain internal

Website implementation determines:

- how approved truth is presented
- how public audiences navigate it
- how content is structured for usability
- how SEO surfaces are managed
- how conversion paths are executed

---

## Operating Rule

If a website page conflicts with a platform governance document, the governance document controls.

If a public route implies a structure that is not supported by governance documentation, the route must be treated as transitional until reviewed.

If SEO language pressures the platform into architectural distortion, the platform architecture controls.

---

## Examples

### Example 1 — CEH Standard

The CEH Standard may be communicated through a public website page.

However, the standard itself is governed by platform methodology, terminology, route classification, source-of-truth documents, and approved governance artifacts.

The website page is not the standard.

---

### Example 2 — CEH Infrastructure Index

The CEH Infrastructure Index may have public-facing pages, benchmark language, or investor-facing explanations.

However, its institutional role, methodology boundaries, and relationship to CEH Standard must be governed at the platform layer.

The website page is not the index.

---

### Example 3 — DGE&I Commercialization Layer

DGE&I-related language may appear in strategic materials or future commercial surfaces.

However, DGE&I commercialization must remain distinct from CEH Standard and CEH Infrastructure Index unless explicitly governed otherwise.

A website reference does not create platform-level integration.

---

## AI Operating Expectations

AI systems must distinguish between:

- editing a website
- changing platform architecture
- updating governance truth
- restructuring canonical relationships
- improving public language
- modifying institutional meaning

When uncertainty exists, AI systems must defer to the SOURCE_OF_TRUTH_HIERARCHY.md document.

---

## Non-Negotiable Principle

The website is a communication layer.

The platform is the operating system.

Do not confuse the surface with the system.
