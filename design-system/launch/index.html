§ 08Export

Export / deploy instructions

Three paths: (A) push into the existing GitHub repo on a feature branch and use Netlify deploy preview; (B) export as a local repo and deploy fresh; (C) hand off the standalone HTML for review. The repo path is recommended — it aligns with the existing main / staging branch strategy.

A — Push to the GitHub repo (recommended)

  1. Download this project

    Use the project download from the top-right of this workspace, or ask Claude to present the project for download. You'll get a zip of everything in the file tree above.

  2. Clone the repo and create a feature branch off staging
    # clone the existing repo
git clone git@github.com:danielcobb007-debug/oakridgemanagement.git
cd oakridgemanagement

# branch off staging per BRANCH_STRATEGY.md
git checkout staging
git pull
git checkout -b feature/design-system-v1
  3. Copy the new files into the repo

    Unzip the project export and copy these directories into the repo root, preserving structure:

    colors_and_type.css
ui_kits/public-site/
ui_kits/investor-portal/
assets/orm-favicon.svg
assets/dg-favicon.svg
assets/dg-logo.svg
README.md          # overwrites or merges with the existing repo README

    Do not overwrite the existing assets/css/shared.css, assets/css/investor-theme.css, or netlify.toml — those are the existing deployment's source of truth. The new system reads from ui_kits/public-site/orm-public.css and ui_kits/investor-portal/partner-portal.css independently.

  4. Wire the routes

    Decide which surfaces this PR replaces. Recommended minimal landing:

    # public homepage
cp ui_kits/public-site/index.html index.html
# OR keep both during cutover:
mkdir -p preview-v1
cp ui_kits/public-site/index.html preview-v1/index.html

# investor portal landing
cp ui_kits/investor-portal/index.html investor/platform/index.html

    Fix relative paths after copying — the kits assume ../../assets/ for favicons. Update hrefs if the file lands at repo root.

  5. Push the branch and open the Netlify deploy preview
    git add .
git commit -m "design-system v1: ORM public + DGE&I portal"
git push -u origin feature/design-system-v1

    Netlify will auto-build a deploy preview URL for the PR (per NETLIFY_DEPLOYMENT_MAP.md — staging environment, AI-assisted iteration safe zone). Share that URL for counsel + sponsor review. Do not merge to main until every Must item in § 07 is cleared.

  6. Promotion to production

    After all Must items clear: open a PR from feature/design-system-v1 → staging, validate the staging deploy, then PR staging → main. main is the production-protected branch — only approved deployments land here.

B — Local repo / fresh deploy

  1. Initialize a clean repo from the export
    unzip oak-ridge-management-design-system.zip
cd oak-ridge-management-design-system
git init
git add .
git commit -m "initial: ORM design system v1"
git remote add origin git@github.com:<org>/<repo>.git
git push -u origin main
  2. Add the minimal netlify.toml

    Copy the gating + redirect rules from the existing deployment's netlify.toml (in Oak Ridge Management - Documents/) — specifically the /investor/platform/* Identity gate and the trailing-slash canonicalization redirects. Set [build] publish = "." — this is a static site, no build step.

  3. Connect Netlify and deploy

    In Netlify: New site → Import from Git → select the repo → branch main → publish directory .. Add the production domains (oakridgemanagement.net, etc.) per CANONICAL_DOMAIN_REGISTRY.md. Enable Netlify Identity for the investor-role JWT before pointing real DNS.

C — Standalone HTML handoff (review only)

  1. Use the bundled review file

    The file ORM Design System Review.html at the project root is a fully self-contained single-file artifact (1.08 MB, no external dependencies, works offline). Forward it for non-technical review. It contains the consolidated screenshots + caveats but is not deployable — it's a review snapshot only.

Note on the existing repo. The local Oak Ridge Management - Documents/ folder contains a working Netlify deployment with its own governance docs (00_Governance/, 10_Operations/). The new design system is additive — drop the new files into ui_kits/, keep the existing routing, favicons, and governance scaffolding as-is. The two coexist cleanly until cutover.
